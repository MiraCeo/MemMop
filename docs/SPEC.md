# MemMop 产品规格

这份文档记录**决定**，不记录实现。用途：新库从零重建时的唯一依据；也是半年后回看"当初为什么这么定"的答案。

---

## 1. 定位

**一个让人看清内存被什么占着、并在需要时精确释放的工具。** 不是"让电脑变快"的工具。

因此有三条不可违背的原则：

1. **不承诺变快。** 待机内存本就计入"可用"，清它不会让可用变大
2. **不隐瞒代价。** 每个清理项旁必须写明它会让什么变差
3. **不伪造数字。** 没有释放就写"无变化"，不显示负数、不四舍五入成好看的值

---

## 2. 界面结构

三个主界面：**主页 / 设置 / 关于**。名称都是地点，不用动词命名页签。

### 2.1 主页

自上而下：

| 区块 | 内容 |
|---|---|
| 内存区域 | 7 个清理项。每项一行勾选 + 名称 + 代价说明（第二行，灰色 11px）；右侧显示"上次释放 X" |
| 进程占用 | 折叠组。展开时刷新，显示前 10 名：名称 / 实例数 / 专用工作集；底部一行"合计（专用工作集，不含共享页）X" |
| 自动清理 | 只读状态行："自动清理：关闭" 或 "自动清理：每 N 分钟 · 可用低于 M% 时" |
| 内存条（固定页脚） | 物理内存四段条（活动/已修改/待机/空闲 + 数值）与已提交条；右侧 `?` 提供口径说明 |
| 清理按钮（固定页脚） | 全宽，"清理" |

### 2.2 设置

| 分组 | 内容 |
|---|---|
| 通用 | 语言（简中/英）、字号（小/标准/大） |
| 开关（7 项） | 关闭时最小化到托盘 · 静默启动 · 开机自启 · 显示清理通知 · 显示已提交 · 详细内存信息 · 自动清理只做保守操作 |
| 清理热键 | 折叠组，修饰键 + 按键 |
| 排除的进程 | 折叠组。搜索框 + 进程下拉（显示 `名称（N 个进程）`）+ 已排除列表 |
| 自动清理 | 两个滑块：间隔（0=关闭）、低内存阈值（0=关闭） |
| 操作 | 重置（带确认对话框） |

### 2.3 关于

名称 + 版本、一句话说明（基于 WinMemoryCleaner 修改、绿色免安装、设置存当前用户）、指向仓库的按钮。后续可加许可证、反馈入口。

### 2.4 托盘

- **左键单击**：显示并置前（**永不隐藏**——双击曾等于显示又隐藏）
- **右键菜单**（三组）：状态行（已用/总量、上次清理）→ 主页 / 设置… → 清理 → 退出
- 清理进行中只禁用「清理」一项，导航与退出始终可用
- 图标：16×16 单尺寸（待改多尺寸）

---

## 3. 设置项与默认值

| 设置 | 默认 | 理由 |
|---|---|---|
| 关闭时最小化到托盘 | **开** | 托盘驻留工具，✕ 不该等于退出 |
| 静默启动 | **开** | 与上一条配套；首次启动弹一次气泡说明 |
| 开机自启 | 关 | 需要系统级改动，由用户主动选择 |
| 显示清理通知 | 开 | 自动清理后唯一的反馈 |
| 显示已提交 | 开 | 判断"清理能不能解决问题"的关键指标 |
| 详细内存信息 | 开 | 四段构成；关掉只看总量 |
| 自动清理只做保守操作 | **开** | 见 §4.3 |
| 自动清理间隔 | 0（关） | 默认不自动动用户的机器 |
| 低内存阈值 | 0（关） | 同上 |

---

## 4. 行为规则

### 4.1 关闭与启动

- 点 ✕ → 最小化到托盘（默认）
- **首次**隐藏时弹一次气泡「已最小化到托盘」
- **静默启动**时弹同一条气泡（否则开机后"什么都没发生"）
- 气泡只弹一次，持久化标记

### 4.2 排除的进程

- 按**进程名**匹配（Windows 返回的原名：无 `.exe`、保留大小写、保留空格）
- 比较忽略大小写
- 同名进程全部生效（`chrome` 一次排除 28 个）
- 存储不做任何归一化（`ToLower` / 去空格会破坏匹配——曾经踩过）

### 4.3 自动清理

- 自动清理**只执行安全子集**：清理待机缓存、写回已修改内存、合并重复内存页、注册表缓存整理
- 排除在外：收缩程序驻留内存（造成卡顿）、收缩系统缓存（持久影响）
- 用户可在设置里关掉「只做保守操作」，届时自动清理执行其勾选的全部项目
- 被排除的两项在说明里标注「自动清理默认跳过」

### 4.4 上次释放

- 每个区域记录"本区域内可用内存的前后差"
- `≤ 0` 显示「无变化」，不显示负数
- **单位统一为字节**，界面按 `ToMemoryUnit()` 格式化

### 4.5 通知

三行结构：

```
已手动清理内存，耗时 17.0 秒
内存占用 释放 1.5 GB
已提交 释放 5.6 MB
```

- 自动触发时首行为「已自动清理内存」
- 释放量 ≤ 0 时该行去掉动词，写「未释放」

### 4.6 同名进程

- 排除、统计、清理都按进程名聚合
- 界面必须显示数量（`chrome 22`），否则用户以为是单个

---

## 5. 指标口径

| 用途 | 指标 |
|---|---|
| 四段条 | 活动 / 已修改 / 待机 / 空闲（任务管理器口径） |
| 进程占用表 | **专用工作集**（`PROCESS_MEMORY_COUNTERS_EX2.PrivateWorkingSetSize`） |
| 合计 | 必须标注「不含共享页」，否则会与系统"使用中"对不上 |

**禁止**用工作集求和：28 个 chrome 各算一遍共用 DLL，求和会超过物理内存总量。

---

## 6. 文案原则

1. **代价必须写在界面上**，不藏在悬停里（悬停对触屏和键盘用户不成立）
2. 每句代价控制在 10–18 字，读起来像标签不像段落
3. 删掉零信息的话（"效果因环境而异"），保留具体风险（"收益不确定"）
4. 术语不要求用户重新学：状态语言复用四段条的词（活动/已修改/待机/空闲），操作用动词（清理/收缩/合并/写回）

---

## 7. 版本与交付

- 版本号 = 构建号三位数字直译：`064` → `0.6.4`
- 交付物命名：`MemMop_0NN.exe`
- 单文件、无外部依赖、绿色免安装
- 需要管理员权限（`requireAdministrator`）
- 开机自启用**登录触发的计划任务**（`HighestAvailable`），不弹 UAC

---

## 8. 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 自动更新 | 上游的实现是僵尸功能；且更新器会把用户拉回未修改的版本 |
| 捐赠入口 | 与工具定位无关 |
| 托盘图标配色系统 | 16px 上画两位数既看不清又多余 |
| 按区域着色分组 | 操作会跨段转移页面（收缩工作集后进入待机/已修改，不是直接变空闲），强行绑定会误导 |
| Windows 服务模式 | 与"绿色免安装、用户会话"冲突 |

---

## 9. 差异化的落点：可信的交互

本项目要做的不是"界面好处"或"功能多"，而是**同样底层能力下，更可信的交互**。

### 三条验收标准（每次发布前逐条过）

| 标准 | 含义 | 可验证的检查 |
|---|---|---|
| **效果真实** | 区分"状态变化"与"性能收益"，不用好看的数字代替实际效果 | 无释放时写"无变化"；合计标注"不含共享页"；口径与任务管理器一致 |
| **行为透明** | 告诉用户做了什么、为什么做、代价是什么 | 每个清理项旁有代价说明；通知说明本次执行了什么 |
| **控制可靠** | 用户授权范围内的操作不被绕过 | 排除名单不被系统级回退绕过；自动清理不执行用户只授权手动的项 |

### 不能用作设计依据的东西

- "WMC / Mem Reduct 有这个功能" → 不是理由
- "多加一个选项会更强大" → 不是理由
- 唯一判据：**能不能用一句人话说清它做什么、代价是什么**

## 10. 模块划分

职责分离，使"换界面"不牵动清理逻辑，"换底层实现"不破坏界面。

| 模块 | 职责 | 依赖方向 |
|---|---|---|
| **内存监测** | 读取系统状态、进程占用、统计数据 | →（无） |
| **清理引擎** | 封装系统 API、执行操作、返回结构化结果 | → 内存监测 |
| **策略与安全** | 自动触发、排除名单、权限、风险约束 | → 清理引擎 |
| **UI** | 展示、接受操作、解释结果 | → 以上全部，通过接口 |
| **配置与日志** | 保存设置、记录执行行为与错误 | ← 被以上依赖 |

约束：

- UI 不直接调用系统 API
- 清理引擎不知道"自动"还是"手动"，只接受区域集合
- 策略层决定"这次执行哪些区域"（手动 = 用户勾选；自动 = 用户勾选 ∩ 安全子集）
